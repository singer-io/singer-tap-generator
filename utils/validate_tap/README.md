# Singer Tap Validator

A comprehensive static and runtime validation tool for Singer taps. Validates 9 key areas of any tap and produces a terminal summary, a JSON report, and an HTML report.

---

## Files

| File | Purpose |
|------|---------|
| `tap_validator.py` | Main validator script |
| `validation_config.json` | Your local config (git-ignored credentials paths) |
| `validation_config.sample.json` | Template to copy for a new tap |
| `tap_credentials.json` | Tap credentials for live discovery/sync checks |

---

## Quick Start

```bash
# Static analysis only (no credentials needed)
python tap_validator.py --tap-dir /path/to/tap-name

# Full run (live discovery + sync) with JSON + HTML reports
python tap_validator.py --tap-dir /path/to/tap-name \
    --tap-config tap_credentials.json \
    --output report.json \
    --html

# Run from a config file
python tap_validator.py --config validation_config.json

# Specific checks only
python tap_validator.py --tap-dir /path/to/tap-name --checks schema catalog_validation
```

## Checks

| # | Check | Mode | What It Validates |
|---|-------|------|-------------------|
| 1 | `python_upgrade` | Static | CircleCI uses Python 3.12+; `setup.py` has versioned `singer-python`, `requests`, `backoff` |
| 2 | `metadata` | Static | `replication-method` and `parent-tap-stream-id` are written in catalog metadata code |
| 3 | `unauth_exclusion` | Static | `discover.py` handles 403 responses, excludes inaccessible streams from the catalog |
| 4 | `unit_tests` | Static + pytest | Unit test directory exists, key areas covered (client, discover, sync), coverage measured |
| 5 | `integration_tests` | Static | All standard test files present (bookmark, discovery, pagination, all_fields, automatic_fields, start_date) |
| 6 | `discovery` | **Runtime** / Static | Executes `tap --discover`, validates catalog JSON structure, stream count, key_properties |
| 7 | `sync` | **Runtime** / Static | Executes Sync1 (no state) + Sync2 (with state); validates records, schemas, bookmarks, pagination |
| 8 | `schema` | Static | Schema files: root type is `object`, all fields nullable, date-time fields have `format: date-time` |
| 9 | `catalog_validation` | Static (catalog file) | Full Singer catalog validation — see [Catalog Validation](#catalog-validation) below |

### Catalog Validation

Per-stream checks (FAIL-level unless noted):

- All required top-level fields present: `tap_stream_id`, `stream`, `key_properties`, `schema`, `metadata`
- `stream` == `tap_stream_id`
- Root breadcrumb `[]` metadata entry exists
- `table-key-properties` present and matches `key_properties`
- `forced-replication-method` present and is `INCREMENTAL`, `FULL_TABLE`, or `LOG_BASED`
- `valid-replication-keys` present for `INCREMENTAL` streams
- `inclusion` set on root metadata (WARN)
- Every `schema.properties` field has a metadata entry (WARN)
- Every property metadata entry has a valid `inclusion` value (`automatic` / `available` / `unsupported`)
- Key property fields have `inclusion: automatic`
- Replication key fields have `inclusion: automatic`

Cross-stream check:

- Every `parent-tap-stream-id` references a stream that actually exists in the catalog

**Catalog source priority:**
1. `<output_dir>/catalog.json` — generated by the `discovery` check at runtime (preferred)
2. `catalog.json` in the tap root — checked-in or manually generated

## Static vs Runtime

Checks 1–5, 8, and 9 are **always static** (no credentials needed).

Checks 6 (`discovery`) and 7 (`sync`) run in **two modes**:

| Mode | When | What happens |
|------|------|-------------|
| **Runtime** | `--tap-config` provided AND no placeholder values detected | Executes the tap executable against the real API |
| **Static** | No `--tap-config`, or credentials have placeholder values | Analyses `discover.py` / `sync.py` code patterns |

The validator auto-detects placeholder values (`YOUR_`, `<VALUE>`, `PLACEHOLDER`, etc.) and falls back to static mode automatically.

## Setting Up Live Credentials

1. Copy `validation_config.sample.json` → `validation_config.json`
2. Edit `tap_credentials.json` — add your tap's real credentials (copy fields from the tap's `config.json.example`)
3. Set `tap_dir` in `validation_config.json` to point to the tap you want to validate
4. Run: `python tap_validator.py --config validation_config.json`

All keys starting with `_` in `tap_credentials.json` are treated as metadata comments and are **not** passed to the tap executable.

## Configuration File

Copy `validation_config.sample.json` and fill in your paths:

```json
{
  "tap_dir":    "/path/to/tap-name",
  "tap_config": "/path/to/tap_credentials.json",
  "venv":       "",
  "output_dir": "",
  "timeout":    600,
  "checks": [
    "python_upgrade", "metadata", "unauth_exclusion",
    "unit_tests", "integration_tests",
    "discovery", "sync",
    "schema", "catalog_validation"
  ],
  "output":    "validation_report.json",
  "html":      "validation_report.html",
  "verbose":   false,
  "fail_fast": false
}
```

| Field | Default | Description |
|-------|---------|-------------|
| `tap_dir` | *(required)* | Path to the tap directory |
| `tap_config` | *(optional)* | Credentials JSON — enables live discovery/sync |
| `venv` | auto-detected | Path to the virtualenv with the tap installed |
| `output_dir` | `<tap_dir>/validator_output/` | Where runtime artifacts are written (catalog, sync output, state) |
| `timeout` | `600` | Max seconds per tap subprocess |
| `checks` | all | Subset of checks to run |
| `output` | *(optional)* | Save JSON report — tap name is auto-prefixed |
| `html` | *(optional)* | Save HTML report — tap name is auto-prefixed |
| `verbose` | `false` | Print full per-check detail lines to the terminal |
| `fail_fast` | `false` | Stop after the first FAIL |

## CLI Reference

```
python tap_validator.py [options]

Options:
  --tap-dir PATH        Path to the tap directory (required)
  --tap-config FILE     Tap credentials JSON — enables runtime discovery/sync
  --venv PATH           Virtualenv with the tap installed (auto-detected)
  --output-dir PATH     Directory for runtime artifacts
  --timeout SEC         Subprocess timeout in seconds (default: 600)
  --checks CHECK [...]  Subset of checks: python_upgrade metadata unauth_exclusion
                        unit_tests integration_tests discovery sync schema catalog_validation
  --output FILE         Save JSON report (tap name auto-prefixed)
  --html [FILE]         Save HTML report (default filename: report.html, tap name auto-prefixed)
  --verbose / -v        Print detailed per-check output
  --config FILE         Load all options from a JSON config file
  --fail-fast           Stop after first FAIL
```

### Output File Naming

Report filenames are automatically prefixed with the tap name so reports from different taps never overwrite each other:

```
--output report.json          →  tap-gitlab_report.json
--output my_report.json       →  tap-gitlab_my_report.json
--html                        →  tap-gitlab_report.html
--html custom.html            →  tap-gitlab_custom.html
```

## HTML Report

Pass `--html` to generate a self-contained HTML report alongside the JSON report:

```bash
python tap_validator.py --config validation_config.json --html
```

The HTML report includes:
- Coloured overall status banner (green / red / yellow)
- Summary pills showing Passed / Failed / Warnings / Skipped counts
- One card per check with a status badge and summary line
- Collapsible **Details** section per check (click the arrow to expand)
- `ERROR:` lines highlighted red, `WARN:` lines highlighted yellow inside details

No external dependencies — the file is fully self-contained and opens in any browser.

---

## Virtualenv Auto-detection

The validator searches for the tap executable in this order:

1. `--venv` argument (if provided)
2. `<tap_dir>/.venv/` or `<tap_dir>/venv/`
3. `workspace/taps/virtual_envs/<tap-name>/`
4. `workspace/Sample-taps-test/virtual_envs/<tap-name>/`
5. System `PATH`

## Examples

```bash
# Quick schema check on tap-gitlab
python tap_validator.py --tap-dir ../../taps/tap-gitlab --checks schema

# Full static analysis, verbose output
python tap_validator.py --tap-dir ../../taps/tap-aftership -v

# Live run with reports
python tap_validator.py \
    --tap-dir ../../taps/tap-aftership \
    --tap-config tap_credentials.json \
    --output report.json \
    --html \
    --verbose

# Validate only the catalog (works with catalog.json in tap root)
python tap_validator.py --tap-dir ../../taps/tap-aftership --checks catalog_validation

# Run from config file
python tap_validator.py --config validation_config.json
```
